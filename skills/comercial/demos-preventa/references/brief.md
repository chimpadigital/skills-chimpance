# El brief — insumo de entrada

Santiago pasa el brief al **inicio de la sesión** (lo arma con ChatGPT), en texto/markdown, con los recursos de marca adjuntos o linkeados. Es la base para interpretar el dolor, investigar la jerga y armar el key visual + estructura + copy.

No siempre va a venir completo. Con los bloques ⭐ alcanza para arrancar; lo que falte se cubre con defaults sensatos y placeholders (marcándolos como provisorios).

## Qué debe contener

**1. La marca / el cliente** ⭐
- Nombre y rubro.
- Qué hace / qué vende (2-3 líneas).
- A quién le habla (público / cliente ideal).
- Personalidad de la marca (3-5 adjetivos).
- Competidores o referentes del rubro.
- URL del sitio web actual, si tiene (para analizarlo: marca, tono, jerga, qué tienen hoy).

**2. El punto de dolor** ⭐ *(lo más importante — es el eje del prototipo)*
- ¿Qué le duele hoy? (situación actual, frustración concreta).
- ¿Por qué es un problema? (qué le cuesta: plata, tiempo, imagen, clientes…).
- ¿Qué probó antes y por qué no le funcionó?
- ¿Qué quiere lograr? (estado deseado).
- El dolor en UNA frase.

**3. Qué le vamos a mostrar / vender** ⭐
- Qué producto digital prototipamos (web, plataforma, app, e-commerce…).
- Qué tiene que lograr ese producto (objetivo).
- Secciones/funciones que sí o sí deben aparecer (las que cierran la venta).
- Qué tiene que sentir/pensar el cliente al verlo.
- Quién decide la compra (perfil del decisor) — para ajustar el tono.

**4. Identidad y recursos disponibles**
- Qué hay: logo, colores, tipografías, manual de marca, fotos… (y en qué formato / links).
- Qué NO hay (para cubrirlo con defaults/placeholders).
- Si no hay casi nada: 2-3 referencias visuales (sitios/apps) que peguen con el rubro.

**5. Inspiración visual / estilo** *(clave para el key visual y para elegir la plantilla)*
- Estilo deseado (moderno, minimalista, audaz, premium, cálido…).
- Qué transmitir (confianza, innovación, cercanía, lujo…).
- Efectos/animaciones o sitios de referencia que gusten.

**6. Datos de contacto y presencia** *(para footer, sección de contacto y realismo institucional)*
- Dirección/es y sucursales/oficinas (con ciudad/país).
- Teléfono/s, WhatsApp, email/s de contacto.
- Redes sociales (links a Instagram, LinkedIn, Facebook, YouTube, X, etc.).
- Horarios de atención, si aplica.
- Datos legales/institucionales (razón social, CUIT, matrículas) si corresponde.
- Ubicación para mapa, si se quiere embeber.
- *(Lo que falte se deja como placeholder marcado ⚠️ para que el cliente complete.)*

## Cómo se pasa
- Texto/markdown pegado al inicio (o archivo `.md`/`.txt`).
- Recursos de marca: archivos adjuntos o links. Logo en **SVG** si se puede.

## Prompt para que ChatGPT arme el brief

```text
Actuá como estratega de marca senior. Necesito un BRIEF para que un diseñador
arme un DEMO FUNCIONAL web de VENTA (pre-venta) que le muestre a un potencial cliente
lo bien que puede quedar su producto digital. Devolvémelo en markdown con estas
6 secciones, y preguntame lo que falte antes de cerrarlo:

1. La marca/cliente (nombre, rubro, qué hace, público, 3-5 adjetivos de
   personalidad, competidores, y la URL del sitio web actual si tiene).
2. El punto de dolor (qué le duele hoy, por qué es problema, qué probó antes,
   qué quiere lograr, y el dolor en UNA frase).
3. Qué le vamos a mostrar/vender (tipo de producto, objetivo, secciones que sí o
   sí deben aparecer, qué tiene que sentir el cliente, perfil del que decide).
4. Identidad y recursos disponibles (logo, colores, tipos, manual, fotos; qué
   falta; referencias si no hay marca).
5. Inspiración visual / estilo (estilo deseado, qué transmitir, efectos/sitios
   de referencia).
6. Datos de contacto y presencia (direcciones/sucursales, teléfonos, WhatsApp,
   emails, redes sociales con links, horarios, datos legales/razón social y
   ubicación para mapa) — todo lo que tengan, para footer y sección de contacto.

Mis datos para arrancar: [pegá acá lo que sepas del cliente]
```
